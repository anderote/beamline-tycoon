# Growable Map & Black Hole Factory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make map size a purchasable resource, so the machines that physically cannot fold — linear colliders — become a land problem, and add a tier-6 Black Hole Factory that needs the largest map in the game.

**Architecture:** Three layers. (1) The compile-time `MAP_EXTENT` constant becomes `state.mapHalfExtent`, saved and growable. (2) Land is bought in +30 half-extent chunks (+60 tiles per side) through the existing `canAfford`/`spendFunding` path, with new ground generated as an annulus. (3) A tier-6 type and a `crystalChannelStage` rung three orders of magnitude above the RF ladder.

**Tech Stack:** Vanilla ES modules; seeded LCG terrain generation; hand-rolled Node tests auto-discovered from `test/*.js`.

**Spec:** `docs/superpowers/specs/2026-08-12-growable-map-and-black-hole-factory-design.md`

## Global Constraints

- **The starting map deliberately SHRINKS, from 71×71 to 61×61** (5,041 → 3,721 tiles, −26%). A map you outgrow is what makes land worth buying. This is not a bit-identical change and must not be treated as one: existing saves keep whatever extent they were saved with, and Task 1 must verify that **every non-collider blueprint still places at 61 tiles**. `xfel-flagship` is the one at risk — 111 tiles of path folded through 2 bends. If it no longer places, stop and raise it rather than shrinking the blueprint.
- **Expansion may never move existing terrain.** The generator's LCG is sequential, so its output depends on iteration bounds; re-running it at a larger extent would relocate every tree. New land is therefore generated by a *separate* annulus function using a **position-hashed** RNG (`hash(seed, col, row)`), which is order-independent and idempotent.
- **`MAP_EXTENT` is duplicated in three files that must agree** — `src/game/map-generator.js:108`, `src/renderer3d/world-snapshot.js:12` (`GRASS_RANGE`), `src/game/agent/observation.js:1`. A literal surviving in any of them is a bug.
- **Money moves only through `spendFunding`** (`Game.js:809`), never `resources.funding -=` directly. The file says so explicitly.
- **Costs are provisional.** Settle them in `scripts/balance-sim.mjs`, not by feel during implementation.
- **Do not commit.** The user decides commit boundaries.
- Art tasks are directives with acceptance criteria, not transcribed geometry, per `CLAUDE.md`.

## Task 2: Annulus generation

**Files:** `src/game/map-generator.js`
**Test:** `test/test-map-expansion.js`

**Interfaces:**
- Produces: `generateAnnulus(seed, terrainBlobs, fromHalfExtent, toHalfExtent)` returning `{ placeables }` for the ring of tiles with `max(|col|,|row|)` in `(fromHalfExtent, toHalfExtent]`.

**Why a separate function:** `generateStartingMap` draws from a sequential LCG, so its output depends on how many tiles it iterates. Calling it with a larger extent would produce a different sequence and move every existing tree. The annulus generator must therefore be **position-hashed** — derive each tile's randomness from `hash(seed, col, row)` so a tile's contents depend only on its coordinates, never on iteration order or on how much land has been bought.

- [ ] **Step 1: Write the failing test**

```js
console.log('\n--- annulus generation is deterministic and order-independent ---');
{
  const A = generateAnnulus(4242, [], 30, 60);
  const B = generateAnnulus(4242, [], 30, 60);
  const key = (r) => JSON.stringify(r.placeables.map(p => [p.type, p.col, p.row]).sort());
  assert(key(A) === key(B), 'same inputs give the same annulus');

  // Every placeable lands strictly inside the new ring, never in old land.
  const inRing = A.placeables.every(p => {
    const d = Math.max(Math.abs(p.col), Math.abs(p.row));
    return d > 30 && d <= 60;
  });
  assert(inRing, 'annulus contains no tile inside the previous extent');

  // Two chained purchases equal one big one — the property that makes
  // expansion order irrelevant.
  const chained = [...generateAnnulus(4242, [], 30, 60).placeables,
                   ...generateAnnulus(4242, [], 60, 90).placeables];
  const direct = generateAnnulus(4242, [], 30, 90).placeables;
  const k = (ps) => JSON.stringify(ps.map(p => [p.type, p.col, p.row]).sort());
  assert(k(chained) === k(direct), '30->60->90 equals 30->90');
}
```

- [ ] **Step 2: Run to verify it fails**

Run: `node test/test-map-expansion.js`
Expected: FAIL — `generateAnnulus` is not exported.

- [ ] **Step 3: Implement**

Add `generateAnnulus` beside `generateStartingMap`. Reuse the existing tree-species and density logic, but drive every random draw from a position hash rather than the sequential `rng()`. Forest clumps whose centres fall in the new ring come from `terrainBlobs`, which is already stored in state and already extends past the map edge (`CLUMP_CENTER_MARGIN`).

The chained-equals-direct assertion above is the design constraint: get that property and determinism follows.

Run: `node test/test-map-expansion.js`
